## اجرا

Python 3.9 یا جدیدتر کافی است. بستهٔ پایتونی اضافه‌ای لازم نیست؛ دستور زیر نیز برای سازگاری با روش تحویل قابل اجراست:

```bash
python -m pip install -r requirements.txt
python main.py --input input.json --output output.json
```

در محیط اجرای واقعی باید سرویس Ollama روی `127.0.0.1:11434` فعال و مدل محلی از قبل دریافت شده باشد. این پروژه چیزی نصب یا دانلود نمی‌کند و از API ابری استفاده نمی‌کند. پس از آماده‌سازی مدل، اجرای برنامه به اینترنت نیاز ندارد.

نام پیش‌فرض `qwen3.8:27b` از عبارت `Qwen3.8 : 27b` در PDF گرفته شده است؛ وجود این نام در Ollama بررسی نشده است. نام دقیق مدل اعلامی مدرس را هنگام اجرا مشخص کنید:

```bash
python main.py --input input.json --output output.json --model "EXACT_LOCAL_MODEL_NAME" --timeout 180
```

به‌جای `EXACT_LOCAL_MODEL_NAME` نام واقعی مدل نصب‌شده را بنویسید. متغیر محیطی `OLLAMA_MODEL` هم قابل استفاده است؛ `--model` اولویت دارد. مقدار timeout برحسب ثانیه و برای هر درخواست است.

## معماری

1. **Solver:** مسئله و قیود را حل می‌کند و یک پاسخ پیشنهادی همراه با خلاصهٔ کوتاه بررسی می‌سازد.
2. **Verifier:** مسئله را مستقل بازبینی می‌کند، پاسخ پیشنهادی را با قیود می‌سنجد و پاسخ نهایی را اصلاح می‌کند.

هر دو مرحله از همان مدل استفاده می‌کنند. معمولاً دو فراخوانی و با احتساب تکرار خطا حداکثر چهار فراخوانی انجام می‌شود. برای دریافت JSON از قابلیت structured outputs در [مستندات رسمی Ollama](https://docs.ollama.com/capabilities/structured-outputs) استفاده شده است. پاسخ‌های نمونه در کد ذخیره نشده‌اند.

## ورودی و خروجی

ورودی یک شیء JSON شامل `id` و `problem` است. خروجی فقط `id` و `answer` دارد؛ خلاصهٔ بررسی و توضیحات داخلی در خروجی نوشته نمی‌شوند. `input.json` یک مثال تازه است و پاسخ مورد انتظار آن `11` است.

```json
{"id": "example_001", "answer": "11"}
```

در خطای اتصال، timeout یا پاسخ نامعتبر، هر مرحله فقط یک بار تکرار می‌شود. اگر مشکل باقی بماند، برنامه با کد خروج ۱ متوقف می‌شود، جزئیات خطا را در stderr می‌نویسد و در صورت قابل‌نوشتن بودن مسیر، JSON معتبر با `answer` خالی تولید می‌کند. پاسخ خالی جواب صحیح محسوب نمی‌شود. نامعتبر بودن ورودی نیز خطا است.
